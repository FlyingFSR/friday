# 语言判定专项:四轮实验结论与落地决定(2026-08-29)

> Internal evaluation notes for the 0.4.0 transcription overhaul, Chinese only;
> summary in the v0.4.0 release notes.

四轮实验共 500+ 次转写(第四轮为手切实验)。原始结果——逐条转写记录、汇总统计、各候选提示词全文——留在维护者本机的评测工作区,不随仓库分发,本文档是它的结论。对照服务器跑在本机 8179/8180 端口,未触碰 Friday 线上使用的 8178。

## 落地决定(已实施于 Friday 源码)

1. **移除 whisper-server 启动参数 `-mc 0`**(WhisperServerManager.buildServerArguments)。
2. **移除启动参数 `--no-timestamps`**(同处)。该参数自 2026-05 基线导入起就在,无任何加入理由记录,实测是英文为主两大故障的根因。
3. **提示词换用 P6 变体**(TranscriptionService.mixedLanguagePrompt):原品牌词表 + 原第一句中文例句 + 新增短英文句 "I use Claude every day。",替换掉原第二句中文例句。精确文本以源码为准,逐字节一致。
4. **新增段落拼接后处理**(TranscriptionService.joinTranscriptSegments):开时间戳后 JSON text 字段在段间含换行、偶发双空格(无内联时间标记);拼接规则为空白折叠为单空格、CJK 与中文标点之间折叠为无。

## 关键机制发现(为什么这么改)

1. **`-mc 0` 会把初始提示词整个屏蔽**——不只是"削弱"。四种提示词(含无提示词)在 `-mc 0` 下输出逐字节相同。已从 whisper.cpp 1.8.3 源码确认:`-mc` 控制 `n_max_text_ctx`,为 0 时初始提示词与窗口间滚动上下文一起被丢弃。这解释了此前"词表里明明有 Claude 却总听成 Cloud"的谜团。
2. **`--no-timestamps` 是丢中文插句与整段误翻译的根因**。同模型同参数同提示词同音频,仅开关时间戳:关→插句 2/2 全丢、long-en-02 整段翻成中文;开→插句全部回收、long-en-02 词错误率 0.0%。第四轮本为验证切段方案的手切实验,定位切点时顺带发现。值得注意:开时间戳后服务器仍把 long-en-02 判为 chinese(0.571),但照样转写出正确英文——说明"误翻译"从来不是语言检测层的故障,而是解码方式的故障。
3. **上下文不会串到下一次录音**。whisper-server 硬编码 `no_context=true`,每个 /inference 请求都是全新解码;`-mc` 只影响同一次录音内部 30 秒窗口之间的条件化。这是去掉它后标点恢复的原因,也是长音频丢句风险的来源(由 P6 提示词兜底,见下)。
4. **提示词里的英文散文句会诱导"中文语音→英文翻译"**(新发现的故障模式):整句英文例句(P1/P2)会把中文品牌句整句翻成英文,P2 还摧毁数字听写(丢八成内容)。反过来,**纯词表无例句(P4)在长中文上是灾难**(60 秒段落 19/19 全丢)——中文例句是承重的。P6 配方:中文例句保结构 + 一句五词短英文当活性成分,在全部中文为主样本上零翻车。对照性反例("Claude 不是 Cloud")无效——把错误答案写进上下文等于教会它。
5. **切段方案可行但已无必要**:手切 + 逐段语言路由确实能救回插句(证明该路线不是死路),但被"开时间戳"严格占优——同等救回效果、一半延迟、零工程改造。且实验证明逐段语言路由本身多余:中文块脱离英文语境后 auto 即可正确识别。
6. **强制 language=en 能根治误翻译但会把插句丢得更干净;强制 language=zh 是灾难**(6/6 翻车、输出繁体)。任何未来自动选语言方案,猜中文必须极保守。
7. 温度为 0 时全部行为确定可复现,此前记为"概率性翻车"的现象实为配置确定性差异。

## 已知代价(诚实记录)

- **插句救回但非完美**:召回 0.85/0.94,句子在、可读,但含错字(「改一行崩三处」→「改行崩散处」)。相比无声删除是质变,但不是干净转写。
- **繁体字**:6→11(时间戳开启把 22 压回 11,仍略高于原状)。Friday 无繁简转换层,繁体会原样进用户文本。候选后续:后处理繁简归一(独立小任务)。
- **延迟**:短听写 +8.6%(中位 1.63s→1.77s),长音频 +23%。体感边缘,可接受。
- **配置是整体验收的**:两个参数移除 + P6 提示词 + 段落拼接是作为一个组合测的,单独改任何一半都必须重跑 21 段样本矩阵。

## 维护警示

- **不要重新引入 `-mc 0` / `--max-context 0`,也不要重新引入 `--no-timestamps` / `-nt`**——前者静默关闭整个提示词偏置(英文词错误率退回 28.6%、标点消失),后者带回丢插句与整段误翻译。有单元测试防守(WhisperServerManagerTests)。
- **不要随手改 mixedLanguagePrompt**——每个成分都是承重的(中文例句防长中文崩溃,短英文句救 Claude 与误翻译;更长的英文会反噬中文)。改动必须用 21 段样本矩阵重新回归。
- 更早的评测记录里写的启动参数是当时的历史事实;复刻"Friday 现状"时以本文档为准。

## 全链路审计遗留清单(2026-08-29)

- **`-sns`(压制非语音符号)保留**:压幻觉的同时,口述的冒号/分号/引号/括号永远转写不出(语音命令"冒号"仍有效)。现有好成绩含此参数;将来若要动,须重跑 21 段回归矩阵。
- **词表激进改写保持现状**:soul/sole→Sol、whispers→Whisper、codec/cortex→Codex 在英文变准后误伤面上升(正经英文词首次能干净抵达规则)。维护者只把这些音当品牌名说,因此维持激进。若将来实际被误伤,收窄顺序:sole/soul > whispers > codec/cortex。
- **`-et 2.4`、`-lpt -1.0` 是库默认值,`-sow` 在当前配置下是空操作**(未开 token timestamps 与 max-len);写着无害但并非调优结果,勿当成有意义的数字。
- **VAD 参数块是死配置**:唯一调用点传 vadModelPath=nil。若将来启用,注意 `-vmsd 15` 的 15 秒硬切会削弱移除 `-mc 0` 后恢复的窗口间上下文,须重新回归。
- cloud→Claude 规则不冗余:最终配置回归里 brand-03 仍出 Cloud,提示词只缓解未根治,规则保留。
